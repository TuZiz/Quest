# 六卡像素菜单

Quest 的章节、任务两个菜单共用三列两行布局，每页六项。单张卡片占三列两行槽位；整张卡片共用任务操作和悬浮信息。翻页继续更新变化的槽位，不清空或重新打开菜单。

当前任务页沿用 V10 图标纸卡；章节页按用户确认的 V9 显示六张编号书册：第一章为真实入口，第二至第六章为未开放的展示卡。上半区为五行 45 槽、176×108 像素；四行内容、一行导航，返回、页码、分类和关闭按钮统一基线。展示卡参与现有分页；只有一页时隐藏箭头模型，保留无动作的原槽位。

## 文件位置

- 插件：`target/Quest-1.0.0.jar`，Java 25。
- 服务端菜单：`plugins/Quest/gui/chapters.yml`、`plugins/Quest/gui/tasks.yml`。
- 素材和模型：`plugins/CraftEngine/resources/quest-journal-ui`。
- 制作记录、生成工具和预览：`plugins/CraftEngine/design/quest-journal-20261112`。

图片、模型和字体 Glyph 不进入 Quest 源码或 JAR；插件只读取菜单里的模型映射和原生槽位分组。默认打包的原版菜单不被强制替换。

## 数据与显示

只修改显示和槽位分组，不修改任务定义、任务条件、奖励或数据库结构。卡片状态由当前任务状态控制，计数来自真实目标进度，多目标任务显示已满足的目标数之和。目标总量超过 99 时卡片显示百分比，完整数值始终保留在悬浮信息中。

未开放书册只存在于 `gui/chapters.yml` 的 `cards.chapter-previews`，不进入业务章节列表，没有任务、进度、奖励或点击动作。当前 `cards.chapter-preview-category: 'ALL'`，主线、支线和特殊共用真实章节及锁定封面；进入章节后仍按所选分类过滤任务，没有该类任务时保持空列表。未来存在同 `order` 的真实章节时，展示卡自动让位给真实章节。新增展示卡或真实章节超过六项后，使用原有上下页按钮在菜单内翻页；当前六项为一页，页码 `1/1`。旧值 `MAIN`／`SIDE`／`SPECIAL` 仍支持限定单一分类。

任务页四、五字名称完整一行，六字名称按上下分区展示。“前往石址击杀三只僵尸”的卡面使用文件对应简称“初次试炼”，原任务名称、条件、完整 Lore 均不变。普通点击与权限规则沿用原实现；只允许追踪进行中的任务。

同一张卡片只在中央上方的槽位绘制模型，其他五个槽位是透明命中载体。绘制载体使用原版物品，避免自定义物品提供方覆盖模型；命中载体由 CraftEngine 注册。没有接受资源包的玩家仍看到原版任务物品和玻璃装饰。

## 后续维护

改任务名、图标或增加任务后，在服务端 design 目录运行 `build_runtime_skin.py`；当前入口调用 `build_polished_runtime.py` 和 `build_chapter_previews.add_previews`，保留默认第二至第六章封面，只输出到 `polished-stage`，不直接覆盖运行素材。新任务 ID 需要添加到对应 GUI 的 `cards.models`，验证后再替换运行资源并重载。仅改目标数量不需要重新生成贴图，动态数字与百分比由物品组件驱动。新增展示卡需要配置独立合法模型 ID 和对应贴图，不会自动编写新章节任务。

旧 `install_menu_config.py` 读取首次备份，禁止对已修改配置重复运行。此次 `install_polished_runtime.py` 同样是一次性安装器，检查备份与当前哈希并保留被替换目录，二次调用会停止。未知任务显示通用“查看详情”卡片，悬浮信息仍为真实内容。制作工具、验证图及字体文件仅保存在服务端 design，不进入 Quest 仓库资源或 JAR。
